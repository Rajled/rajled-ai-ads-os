# Sprint S1-006 - Google Ads SDK and Connectivity

**Status:** ACCEPTED

**Release:** v0.2.0-alpha.4

---

## Sprint Goal

Introduce the official Google Ads PHP SDK, establish a secure native-client boundary, and verify the first live read-only API operation from the WordPress hosting environment.

---

## Completed Work

### Composer and Runtime Baseline

Sprint S1-006 introduced Composer for third-party dependency management.

- The minimum PHP version was raised to PHP 8.3.
- `composer.json` and `composer.lock` became tracked project files.
- `vendor/` remains ignored by Git.
- Production WordPress ZIP packages include `vendor/` so hosting does not require Composer.
- The existing SPL autoloader remains responsible for `Rajled\AiAdsOs\` classes.
- Composer autoloading is loaded first and is responsible for third-party libraries.

The installed SDK is:

```text
googleads/google-ads-php v33.5.0
Google Ads API V24
```

### Native SDK Boundary

The native SDK bootstrap was implemented under:

```text
src/Integration/GoogleAds/Sdk/
```

Key classes include:

- `GoogleAdsSdkFactory`, which builds configured native SDK clients;
- `GoogleAdsSdkClient`, which wraps native client access;
- `GoogleAdsConnectivityChecker`, which performs the read-only connectivity operation;
- `GoogleAdsConnectivityHealthCheck`, which exposes sanitized operational status.

Official SDK types remain inside the Google Ads SDK boundary.

### Credential Configuration

The WordPress plugin bootstrap maps externally defined constants from `wp-config.php` into the existing application configuration.

Supported credential categories are:

- developer token;
- OAuth client ID;
- OAuth client secret;
- refresh token;
- optional login customer ID.

Credential values are defined outside the repository. They are not stored in plugin source, WordPress options, logs, release documentation, or release packages.

### OAuth and Google Ads Environment

The accepted environment includes:

- a configured Google Cloud project;
- an OAuth consent and client configuration;
- an MCC account relationship;
- an approved Google Ads developer token;
- a locally generated OAuth refresh token.

OAuth refresh-token generation is supported by the local developer tool:

```text
tools/dev/generate-google-ads-refresh-token.php
```

The tool is excluded from production ZIP packages and does not persist credentials in the repository.

### WordPress Deployment

Production-style ZIP packages contain the complete plugin runtime, including Composer dependencies. The package can be uploaded through the WordPress administration interface without running Composer on the host.

The bootstrap fails clearly when `vendor/autoload.php` is unavailable and remains safe in isolated or command-line execution contexts.

### Connectivity Health Panel

The WordPress dashboard includes an administrator-only Google Ads Connectivity panel.

The panel:

- runs only after an explicit protected POST action;
- performs credential preflight validation;
- constructs the native client through `GoogleAdsSdkFactory`;
- calls only `ListAccessibleCustomers`;
- returns sanitized status and account-count information;
- performs no query, search, or mutate operation during an ordinary GET request.

---

## Live Acceptance

The first successful live Google Ads request was completed through the production flow:

```text
CredentialsManager
    -> GoogleAdsSdkFactory
    -> GoogleAdsSdkClient
    -> GoogleAdsConnectivityChecker
    -> ListAccessibleCustomers
```

The accepted request returned seven directly accessible account resource names. No identifiers or resource names were written to documentation or logs.

---

## Architecture Outcome

Sprint S1-006 moved the Google Ads integration from its pre-connectivity foundation to verified, read-only API communication.

The SDK remains isolated in Integration, WordPress remains the runtime and presentation host, and the Domain Layer remains independent from Google Ads and WordPress.

---

## Out of Scope

Sprint S1-006 did not implement:

- campaign retrieval;
- metrics retrieval;
- account selection;
- Google Ads mutations;
- automated optimization;
- business engines.
