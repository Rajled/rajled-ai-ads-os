# SPR-002 — Infrastructure Layer

**Project:** RajLED AI Ads OS
**Sprint:** S1-002
**Target Version:** v0.2.0-alpha.1
**Status:** Ready for Implementation

---

# Sprint Goal

Introduce the infrastructure layer required for scalable, modular and maintainable development.

The objective is to remove object creation responsibilities from the Kernel and introduce dependency management through a Service Container.

No Google Ads functionality is implemented in this sprint.

---

# Scope

## S1-002-01 Service Container

Create:

src/Core/ServiceContainer.php

Responsibilities:

- register services
- singleton support
- lazy instantiation
- resolve services
- dependency lookup

Required methods:

register()

singleton()

has()

get()

---

## S1-002-02 Service Provider Interface

Create:

src/Core/ServiceProviderInterface.php

Required method:

register(ServiceContainer $container): void

---

## S1-002-03 Provider Registry

Create:

src/Core/ProviderRegistry.php

Responsibilities:

- register providers
- boot providers
- maintain provider list

---

## S1-002-04 Core Service Provider

Create:

src/Core/CoreServiceProvider.php

Responsible for registering:

- ConfigurationManager
- Logger
- EngineRegistry
- HealthManager

Kernel should use the provider instead of manually creating objects.

---

## S1-002-05 Kernel Refactoring

Kernel must:

- use ServiceContainer
- load providers
- initialize REST
- initialize Dashboard
- expose version

Kernel should not instantiate business services directly.

---

## S1-002-06 Event Dispatcher

Create:

src/Core/EventDispatcher.php

Initial methods:

listen()

dispatch()

removeListener()

clear()

Internal events only.

No WordPress hooks.

---

## S1-002-07 Dependency Injection

Services should be resolved through the ServiceContainer.

Direct object creation should be minimized.

---

## S1-002-08 Documentation Update

Update:

README.md

CHANGELOG.md

Document infrastructure layer.

---

# Out of Scope

Do not implement:

- Google Ads API
- OAuth
- Snapshot Engine
- Campaign Memory
- Performance Engine
- Recommendation Engine
- AI logic
- Scheduler

---

# Acceptance Criteria

Sprint is accepted when:

- ServiceContainer exists
- ServiceProviderInterface exists
- ProviderRegistry exists
- CoreServiceProvider registers core services
- Kernel uses ServiceContainer
- EventDispatcher exists
- REST endpoints continue working
- Dashboard continues working
- Existing functionality is preserved

---

# Definition of Done

Sprint is complete when:

- implementation finished
- documentation updated
- no regression introduced
- WordPress activation successful
- REST endpoints tested
- implementation reviewed
