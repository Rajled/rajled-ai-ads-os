# Sprint S1-004 — Domain Foundation

**Status:** Planned

**Target Version:** v0.3.0-alpha.1

---

# Sprint Goal

Establish the first version of the Domain Layer as the provider-independent business model of RajLED AI Ads OS.

This sprint transitions the project from infrastructure development towards business domain modelling and prepares the foundation for future Decision Engines.

---

# Architecture Objectives

The sprint introduces the first Domain Layer capable of representing business concepts independently from external integrations.

After completion the platform will provide:

- Domain package structure;
- reusable Value Objects;
- initial Domain entities;
- provider-independent business models;
- mapping contracts between Integration and Domain.

---

# Planned Tasks

## TASK-004.1 — Domain Layer Skeleton

### Objective

Create the Domain Layer package structure.

### Scope

- Common
- Account
- Campaign
- Metrics
- Shared package review

### Definition of Done

- PSR-4 compliant namespaces
- autoload working
- no dependency on Integration
- Shared package either justified or explicitly deferred

### Out of Scope

- business logic
- repositories
- engines

---

## TASK-004.2 — Common Value Objects

### Objective

Introduce reusable immutable Value Objects.

### Scope

- Identifier
- ResourceName
- Money
- Currency
- DateRange
- Status

### Definition of Done

- immutable implementation
- constructor validation
- PHPDoc
- no setters

### Out of Scope

- provider-specific values
- persistence

---

## TASK-004.3 — Campaign Domain Model

### Objective

Implement the first Domain Entity.

### Scope

Campaign containing:

- Identifier
- ResourceName
- Name
- Status
- Budget
- Metrics

### Definition of Done

- Domain-only dependencies
- uses Value Objects
- provider independent

### Out of Scope

- repositories
- persistence
- business workflows

---

## TASK-004.4 — Metrics Domain Model

### Objective

Replace primitive metric arrays with strongly typed Domain objects.

### Scope

- Impressions
- Clicks
- CTR
- Average CPC
- Cost
- Conversions
- Conversion Value

### Definition of Done

- typed properties
- immutable representation where applicable
- no associative arrays

### Out of Scope

- calculations
- analytics
- trend detection

---

## TASK-004.5 — Mapping Contracts

### Objective

Separate Integration from Domain.

### Scope

Interfaces:

- CampaignMapperInterface
- MetricsMapperInterface
- AccountMapperInterface

### Definition of Done

- Integration maps into Domain
- Domain has no Integration dependency

### Out of Scope

- mapper implementations
- provider logic

---

# Definition of Done

The sprint is considered complete when:

- all planned TASKs are accepted;
- documentation reflects implementation;
- Domain Layer has no infrastructure dependencies;
- coding standards are satisfied;
- acceptance tests pass successfully.

---

# Acceptance Tests

Architecture

- Domain has no dependency on Integration.
- Domain has no dependency on Google Ads SDK.
- Domain has no dependency on WordPress.

Implementation

- Value Objects are immutable.
- Campaign uses Domain objects only.
- Metrics are represented by dedicated classes.
- Mapping contracts separate Integration from Domain.

Documentation

- ROADMAP updated.
- DOC-003 updated.
- DOC-004 updated.
- DOC-005 updated.
- CHANGELOG updated.

---

# Risks

- introducing provider-specific terminology into the Domain Layer;
- leaking SDK classes into business models;
- using primitive values instead of Value Objects.

---

# Expected Outcome

Upon completion of S1-004 the project will possess a complete Domain Foundation that serves as the common business language for all future Decision Engines.

This marks the transition from framework development to business-driven architecture.
