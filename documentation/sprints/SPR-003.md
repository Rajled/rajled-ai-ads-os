# SPR-003 - Google Ads Integration Foundation

**Project:** RajLED AI Ads OS
**Sprint:** S1-003
**Target Version:** v0.2.0-alpha.2
**Status:** Ready for Review

---

# Sprint Goal

Introduce the Google Ads Integration Layer foundation required for future provider communication.

This sprint establishes configuration, credential readiness, client and connection contracts, provider registration and health visibility.

No campaign fetching or Snapshot Engine functionality is implemented in this sprint.

---

# Scope

## S1-003-01 Google Ads Configuration

Create:

```text
src/Integration/GoogleAds/GoogleAdsConfiguration.php
```

Responsibilities:

- read Google Ads configuration values from the application configuration
- expose required credential keys
- report missing required values
- avoid exposing secrets through health or public output

---

## S1-003-02 Credentials Manager

Create:

```text
src/Integration/GoogleAds/CredentialsManager.php
```

Responsibilities:

- validate whether required Google Ads credentials are present
- report missing credential keys
- centralize credential access for integration-layer services

---

## S1-003-03 Client Contract and Factory

Create:

```text
src/Integration/GoogleAds/ClientInterface.php
src/Integration/GoogleAds/ClientFactory.php
```

Responsibilities:

- define the Google Ads client adapter contract
- create a client adapter only when required credentials are configured
- avoid direct API calls in the foundation sprint

---

## S1-003-04 Connection Contract and Manager

Create:

```text
src/Integration/GoogleAds/ConnectionInterface.php
src/Integration/GoogleAds/ConnectionManager.php
```

Responsibilities:

- expose Google Ads connection readiness
- report configured and not-configured states
- expose missing credential keys for operational diagnostics
- avoid testing live Google Ads connectivity in this sprint

---

## S1-003-05 Google Ads Service Provider

Create:

```text
src/Integration/GoogleAds/GoogleAdsServiceProvider.php
```

Responsibilities:

- register Google Ads integration services in the ServiceContainer
- keep provider-specific services inside the Integration Layer

---

## S1-003-06 Kernel Provider Registration

Update:

```text
src/Core/Kernel.php
```

Responsibilities:

- register GoogleAdsServiceProvider during kernel creation
- preserve existing core provider and WordPress adapter behavior

---

## S1-003-07 Health Status

Update:

```text
src/Health/HealthManager.php
```

Responsibilities:

- include Google Ads readiness under the `google_ads` health key
- expose status, configured flag and missing credential keys
- never expose credential values

## S1-003-08 Documentation Update

Update:

- README.md
- CHANGELOG.md
- documentation/api/DOC-006-REST-API.md
- documentation/sprints/SPR-003.md

## TASK-003.2 Integration Provider Framework

Create:

```text
src/Integration/IntegrationProviderInterface.php
src/Integration/IntegrationRegistry.php
```

Responsibilities:

- define a provider-independent integration contract
- register integration providers by provider name
- expose integration health statuses without provider-specific HealthManager dependencies
- allow future integrations to register without changing HealthManager

Update:

```text
src/Core/CoreServiceProvider.php
src/Health/HealthManager.php
src/Integration/GoogleAds/ConnectionInterface.php
src/Integration/GoogleAds/ConnectionManager.php
src/Integration/GoogleAds/GoogleAdsServiceProvider.php
```

Responsibilities:

- register IntegrationRegistry in the core service container
- make Google Ads implement IntegrationProviderInterface through its connection contract
- register Google Ads automatically in IntegrationRegistry
- preserve the existing health response shape

---

## TASK-003.3 Google Ads SDK Isolation

Create:

```text
src/Integration/GoogleAds/Sdk/GoogleAdsSdkFactory.php
src/Integration/GoogleAds/Sdk/GoogleAdsSdkClient.php
src/Integration/GoogleAds/Sdk/GoogleAdsSdkException.php
```

Responsibilities:

- isolate future Google Ads PHP SDK details under the SDK namespace
- expose the SDK adapter through the existing ClientInterface contract
- use CredentialsManager to decide whether an SDK client adapter can be created
- keep the adapter safe when the official SDK dependency is not installed
- avoid live API requests

Update:

```text
src/Integration/GoogleAds/ClientFactory.php
src/Integration/GoogleAds/GoogleAdsServiceProvider.php
```

Responsibilities:

- create Google Ads clients through GoogleAdsSdkFactory
- preserve ClientFactory backward compatibility with CredentialsManager construction
- preserve the existing health response shape

---

# Out of Scope

Do not implement:

- Google Ads campaign fetching
- Snapshot Engine
- Campaign Memory
- GAQL queries
- live Google Ads API requests
- OAuth authorization flow
- credential persistence UI
- scheduler
- automatic campaign changes
- AI recommendations
- official SDK live calls

---

# Acceptance Criteria

Sprint is accepted when:

- GoogleAdsConfiguration exists
- CredentialsManager exists
- ClientInterface exists
- ClientFactory exists
- ConnectionInterface exists
- ConnectionManager exists
- GoogleAdsServiceProvider exists
- IntegrationProviderInterface exists
- IntegrationRegistry exists
- Kernel registers GoogleAdsServiceProvider
- CoreServiceProvider registers IntegrationRegistry
- Google Ads registers itself in IntegrationRegistry
- HealthManager consumes IntegrationRegistry instead of a Google Ads-specific dependency
- GoogleAdsSdkFactory exists
- GoogleAdsSdkClient exists
- GoogleAdsSdkException exists
- GoogleAdsSdkClient implements ClientInterface
- ClientFactory returns the SDK adapter through ClientInterface
- HealthManager returns `google_ads` readiness status
- health output does not expose credential values
- no Snapshot Engine code is introduced
- no campaign fetching code is introduced
- documentation is updated
- existing REST and dashboard behavior is preserved
